## 一、它是什么

**AI 原生的工作引擎**（"The AI-native engine for teams and their agents"）：
- 核心命题："A chat ends with an answer. A SoduWork request ends when
  the person who asked signs off."——请求以**验收签收**为终点。
- 多 harness：接 Pi / OpenCode / DeepSeek / Qwen / Kimi / Codex 等，
  按步骤选 agent 与模型（便宜模型干杂活，强模型干关键活）。
- 治理：插件先审后共享、按团队/个人授权、可撤销；角色/用量/成本/
  审计日志；自托管。
- 验证交付：每个请求带验收标准，独立 AI 审查 + 人工终审。
- 形态：Electron 客户端 + FastAPI Hub + 管理台，自托管，MIT。

## 三、与本项目（awesome-teamwork）的关系

**结论：不是竞品，不是地基，是"近邻 + 理念参考 + 潜在集成对象"。**

1. **赛道相邻但问题域不同**：SoduWork 解决"人 + AI agent 的工作分配与
   验收"；本项目解决"人类团队的协作痛点"（我们的 106 张卡里，文档/
   会议/知识/沟通域它完全没碰）。重叠仅在"需求→指派→验收"一段。
2. **理念可直接借鉴**（写入阶段 2 定位参考）：
   - **验收标准先行 + 人工签收**——结构性回应了我们的 P-043（重复
     汇报层）/P-044（维护工作不可汇报）/P-016（节拍脱节）：状态由
     验收动作自动产生，而非人肉填报。
   - **插件库治理**（先审后用、可撤销、授权粒度）——P-038（知识库
     无人治理）/P-037（发布无审核）的组织级答案。
   - **AI 可选可关可审计**——恰好是我们 P-105（AI 锁定）/P-035（遥测）
     要求的反面教材的正确做法。
3. **潜在集成点（远期）**：若我们的任务模型留"执行者=人或 agent"的
   抽象，未来可把任务派发给 SoduWork 的 runner，验收标准即我们的
   任务 DoD。
4. **风险提示**：3 周大、beta、126 open issues——不要现在依赖它做
   任何事；只作参考与观察对象。其 issue #295（run-level 质量评分/
   经验复用提案）值得跟踪。

## 四、对定位阶段的战略信号

AI-native 玩家正在重新定义"团队协作工具"的边界（3 周 3.9k 星）。
对我们意味着：
- 纯人类协作工具的**传统空档依然在**（P-017/P-095：轻重型断层、
  自托管真空），但窗口期内"AI 原生"是加分项而非可选。
- 我们的问题库天然适合"人类协作 + agent 执行者"的混合模型——
  阶段 2 定位时应把"任务可以派给人也可以派给 agent"纳入候选设计。

### 6.1 积极信号

- **治理能力在快速补齐**：11-21 一天的提交集中在审计日志
  （"scoped audit logs searchable/readable/exportable"）、配额预览
  （read-only admin operations）、Skill 目录与策略预览、用量异常检测
  （"trace anomalous usage and estimate unpriced model costs"）、
  无障碍修复（#840-#846）——正是首评里"理念正确"的落地。
- **issue 质量极高**：#939/#940/#938/#933 等均为结构化中文 bug 报告，
  带版本、环境、API 路径、源码行号、期望与实际——社区在按工程标准
  反馈，不是灌水（对比我们的 P-000 卡片格式，可直接借鉴其结构化程度）。

### 6.2 风险信号（更新首评"风险提示"）

- **#931 [Security] 零权限账号可认领任意团队任务并改写任务归属**：
  API 端点只挂 `current_user`，不校验 `task.view`/`task.dispatch`——
  这是**我们 P-034（权限粗且易翻车）的活教材**：再好的治理叙事，
  一个端点漏校验就能击穿。说明"AI 治理强"≠"传统权限稳"。
- **总量 303 open issues**：功能迭代快于稳定性收敛，早期采用风险上升。

### 6.3 架构提案 #295 进展

仍是 open（3 条评论），提出 inner loop 三件事：
A. run-level 质量评分钩子（复用已冻结的验收标准）、
B. memory-informed 路由偏好、
C. 经验在 dispatch 时自动复用。作者来自 CSDN（ZONGYUAN-ROOT），
文件引用已核对 main。**与我们的 P-107（owner+过期）、P-093（部落知识）
同属"让系统从自己的历史里学习"的方向**——值得持续跟踪，但作者自己也
说"alignment first, no PR opened"，短期内不会落地。

### 6.4 修正后的判断

首评"只观察不依赖"的结论**不变且加强**：热度爆发（65%/2 天）说明
赛道竞争在加速，但 #931 证明产品仍在"功能跑在稳定性前面"的阶段。
阶段 2 定位时应把它当作**理念标杆 + 反面教材双重参照**：
学它的验收/治理理念，避它的权限/过早扩张坑。
