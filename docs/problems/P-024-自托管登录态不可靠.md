# P-024 自托管登录态不可靠

## 问题描述

自托管实例的会话/重定向 bug 让用户反复被踢出登录：Leantime 用户遭遇
URL 反复注入 %2F 重定向，"一个会话要登录 40 到 100 次"。与 P-001（接入难）
不同，这是"接通了之后日常用着用着就坏"的可靠性问题。

## 证据

- Leantime#2504（18 评论，自托管环境）："After initial login which takes
  5-10 logins and a refresh because it keeps appending a %2F redirect after
  every login attempt … This means per session, I have to log in anywhere
  from 40-100 times."（首轮代理抓取，列入其报告主清单）

## 现有方案为什么不够

会话可靠性被当成边缘 bug 而非核心质量属性；自托管环境（反代/域名/HTTPS
组合）千差万别，官方测试矩阵覆盖不了，用户就成了免费测试员。

## 可能的解决方向

认证与回跳作为核心链路对待：常见反代配置的自动化测试 + 出错时的
自诊断输出（当前 URL、回调、cookie 状态）。
