# P-007 字段泛滥、优先级失效

## 问题描述

重型项目管理软件里，项目退化成"checklist hell"：任务关联不上 user story，
日历弱，字段不够就加字段，最后所有事项都被标成 TOP-PRIORITY——优先级
体系整体失效。

## 证据

- HN「Ask HN: What sucks in the project management software you use?」
  （39 points / 47 comments），cdcarter："projects quickly turn into checklist
  hell, cannot connect ANYTHING to it's user story, poor calendaring"；
  edoceo："I hate when multiple items get tagged as TOP-PRIORITY."
  https://news.ycombinator.com/item?id=10871076
- 一周 sprint 救火团队（补充，14/44）："requirements are always lacking
  because it's always fires (and everything is P1)"——优先级体系崩坏
  的运行时形态。 https://news.ycombinator.com/item?id=43932449
- Basecamp 多年用户（补充，13/12）："I've never felt this
  disorganized before."——轻结构工具的全局视图缺失。
  https://news.ycombinator.com/item?id=43778151
- SharePoint 错配（补充，SE score 46/14 答）：核心文档协作能力其实
  过关，"只有当组织强行把它当 CRM、ERP 或外部网站用时才会变得难看"
  ——错配使用毁掉工具口碑（softwareengineering.stackexchange.com/q/…）

## 现有方案为什么不足

工具用字段堆砌应对需求复杂度，而不是用结构（目标-故事-任务链）约束信息架构，
复杂度全部转嫁给使用者。

## 可能的解决方向

默认内置"目标→任务"的关联结构，优先级数量硬约束（如同时最多 3 个高优先级）。
