# P-020 买单人与使用人错位

## 问题描述

企业协作套件的采购逻辑是"老板觉得好就行"：一线员工被卡顿客户端、
残缺的 PC 端功能（考勤/工资条被迫切手机）和臃肿功能堆砌消耗，
最高赞评论一针见血："钉钉的用户是企业老板……牛马的体验不重要"。

## 证据

- V2EX「钉钉为什么使用体验很差」（63 回复，2024-04，实测链接与回复数一致）：
  OP："有时候点击工作台的一些功能时，总是点击没反应，被迫重启钉钉"；
  gregy（❤️12）："钉钉的用户是企业老板，只要老板觉得好愿意买钉钉的服务
  就行，牛马的体验不重要"；daohanghao："太复杂了，功能又乱，搞个搜索
  都能要几十秒才搜搜成功"
  https://www.v2ex.com/t/1028650

## 现有方案为什么不足

商业模式决定了价值函数错位，这不是单点 bug 而是结构性问题——
也意味着"以使用者体验为核心"的产品在市场上有存在理由。

## 可能的解决方向

把"一线成员的日用体验"作为第一设计约束（快、少打扰、PC 端完整），
让使用者的口碑成为增长引擎。
