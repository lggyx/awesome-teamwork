# P-043 重复汇报层烧人

## 问题描述

一线的状态更新路径：更新工单 → 站会口播 → 本地 PM 汇报 → 客户 PM
知会 → 客户干系人会议 → 管理层再汇总一遍。社区总结精准：
"What usually burns people out isn't the work it's the duplicate
reporting layers."（111 分 / 69 评论——本轮英文社区最高热度帖）

## 证据

- r/ExperiencedDevs「Does anyone else get status update fatigue?」
  （111 分 / 69 评论），评论："Standup, Jira updates, project updates,
  stakeholder updates, then another manager summary of the same thing.
  At some point you're just restating the same information in different
  formats."；楼主："Update tickets in issue tracker → Provide update
  on tickets at daily standup... Provide this update to local project
  manager, make sure client project manager also knows"
  （Reddit 直连 403，正文经 redlib 镜像读取，规范 URL 如上）

## 现有方案为什么不足

各汇报渠道互不联通，同一信息的 N 次转写全部人肉完成——这是
P-015（工具维护成本）在汇报场景的具象化，也是 P-012（可见性靠
人肉汇报）的孪生问题。

## 可能的解决方向

一处更新、多视图分发（站会视图/干系人视图/管理层视图自动裁剪），
汇报从"生产信息"降级为"确认信息"。
