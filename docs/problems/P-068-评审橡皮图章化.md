# P-068 评审橡皮图章化

## 问题描述

"people pushing on the code generation front, the code reviewing
front, and the laziness front. Eventually they're going to all meet in
the middle"（2026 帖）——AI 写、AI 审、人惰性，三方合流的终点是
评审形同虚设。而"评审"本身早有结构性缺陷："at the 'review' phase
the code is still 'imaginary'... it hasn't been battle-tested."

## 证据

- HN「Does a human still review your code?」（2026，11/23）：以上原文
- HN「Why code "post-reviews" isn't a thing?」（5/6）：如上

## 可能的解决方向

对协作工具的启示：把"验收"从评审环节后移到可运行证据
（测试/演示/指标），而非依赖形式化人审——与 SoduWork 的
"acceptance criteria + 人签收"思路同源。
