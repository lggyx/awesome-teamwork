# P-001 自托管协作工具的身份认证落地难

## 问题描述

自托管团队的管理员部署完工具后，接企业账号体系（LDAP/OIDC/本地密码）这一步
反复失败：要么工具强制依赖第三方 OAuth，要么按文档配置完登录页连按钮都不出现。
部署的热情被第一步浇灭。

## 证据

- Outline#1881「Local Authentication」：👍 275+（实测，另有多类表情合计 300+）、
  百余评论、仍 open（2024-07 被锁定）。原文："I don't like the fact that you need
  a Google or Slack account. I'm sure you'll scare off a lot of people with that."
- Wekan#119：要求对接 LDAP 而非逐个注册，80 👍 / 104 评论，多年后才关闭。
- Vikunja#240：33 条评论里大量用户贴 config.yml 求助，登录页不出现 OpenID 按钮。
- Outline#5564（补充）：OIDC token 刷新失败把用户强制登出——认证接入后
  的运行期可靠性同样翻车。

## 现有方案为什么不足

各工具把认证当成功能开关而非"落地体验"来设计：文档假设太多前置条件，
失败时无诊断信息，社区只能靠评论接龙互相救。

## 可能的解决方向

把"接入企业身份"做成开箱即用的引导流程（诊断输出、配置校验、失败可解释）。
