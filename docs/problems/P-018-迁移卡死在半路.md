# P-018 迁移卡死在半路

## 问题描述

Notion 用户导出 700MB 工作区 zip，导入开源替代品 AppFlowy 报错
（错误还随机变化），被卡在迁移途中；Vikunja 从 Todoist 迁移丢桶结构。
"想换工具"被半路的迁移拦住，用户只能留在旧工具里。

## 证据

- AppFlowy#8862（仍 open）："I exported my Notion workspace as zipfile.
  It is 700Mb. I tried to import it into Appflowy but got this error message:
  Missing ETag in response for part 4"
- Vikunja#254：Todoist 迁移丢 Kanban 桶。
- taiga-back#21（补充）：项目导出丢用户——迁出的数据不完整，落地即缺员。
- HN 27183401（补充，79 分 / 93 评论）："I was on a team that did it
  three times in a year and each time features got lost and work was
  undone."——中途换工具的组织代价。
- V2EX t/371869（补充，48 回复）："上周领导说，要用 tpad，全员更换，
  重新培训。"——行政强制迁移，习惯成本归零重来。
- ShowDoc#ICFEUZ（补充，Gitee）："文档通过markdown压缩包导出后，图片
  还是之前的ip地址，并没有转到新服务器上"——导出的资料实际不可用。

## 现有方案为什么不足

导入功能按"演示可用"标准做，没有按"真实工作区"标准做：大文件、
嵌套结构、失败续传、字段映射报告都是空白。

## 可能的解决方向

把"从主流工具无损迁入"当作核心能力：预检报告、部分失败可重试、
迁移前后差异清单。
