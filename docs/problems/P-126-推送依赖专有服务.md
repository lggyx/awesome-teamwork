# P-126 推送通知依赖专有服务

## 问题描述

自托管邮件/协作工具的移动推送两难：用 Pushover 等专有服务违背自托管
初衷；换 UnifiedPush 又"will create the same Problem for a different
group of Persons"；而 UnifiedPush 支持者强调目标是"instantly wake up
your mobile apps… without having to rely on proprietary services from
Google"——推送这块基础设施的开放性还没解决（与 P-055 自托管无移动
推送是同一问题的两面）。

## 证据

- mailcow#4969（24 👍/2 评论）：mutschler / hede5562 原文，2026-11-22 实抓

## 可能的解决方向

推送通道抽象层：多后端可插拔（FCM/APNs/UnifiedPush/自托管长连接），
管理员自选，用户无感。
